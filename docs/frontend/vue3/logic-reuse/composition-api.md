3. 约定和最佳实践
   1. 命名
      use开头，驼峰命名法
   2. 参数：为了能够被正确追踪，一般结合watch显示跟踪ref或getter，或者watchEffect中调用toValue()
   3. 返回：
      1. 推荐返回包含一个或多个ref的非响应式对象，这样该对象在组件中被解构时依然保持响应性
      2. 从组合式函数中返回响应式对象，会造成解构时失去响应性
      3. 如果你希望以对象的形式使用组合式函数返回的状态，可以使用reactive再包装一次
      ```js
      const state = reactive(useMouse())
      console.log(state.x)
      ```

6. 和其他模式的比较
   1. 和mixin的比较
      1. 不清晰的数据来源
      2. 命名空间冲突
      3. 隐式的跨mixin交流
   2. 和无渲染组件相比
      组合式函数没有额外的组件实例开销
      推荐纯逻辑复用使用组合式函数
      同时复用逻辑和视图时，使用无渲染组件
   3. 和react hooks的对比
      **React**
          1. react hook在每次组件更新时都会被调用
          2. hooks 不能在条件分支中调用
          3. React定义的变量会被一个钩子函数闭包捕获，依赖于用户传入的依赖数组
          4. 昂贵的运算需要useMemo,也需要传入正确的依赖数组
          5. 默认情况，传递给子组件的事件处理函数会导致子组件不必要的更新。子组件默认更新，并需要显示的使用useCallback进行优化，这个依赖同样需要正确的依赖数组，
          6. 要解决变量闭包导致的问题，再加上并发功能，很难推理出一段代码是怎么执行的。并且很不好处理在多次渲染期间需要保持引用的可变状态
            **注意：上述一些与记忆化相关的问题可以通过即将推出的 React Compiler 解决**
      **Vue**
        1. 仅调用setup 一次，不需要担心闭包变量的问题，组合式api并不限制调用顺序，且可以有条件的调用
        2. Vue的响应式系统会自动收集计算属性和侦听器的依赖，不需要手动声明依赖
        3. 无需手动缓存回调函数来避免不必要的组件更新

7. 组合式函数的常见问答
   1. 更好的逻辑复用
   2. 更灵活的代码组织
   3. 更好的类型推导
   4. 更小的生产包体积
